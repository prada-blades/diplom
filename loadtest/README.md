# Нагрузочное тестирование Booking API

Инструмент для нагрузочного тестирования REST API системы бронирования ресурсов.
Написан на Go, не требует внешних зависимостей — только стандартная библиотека.

## Требования

- Go 1.21+
- Запущенный сервер (см. корневой `CLAUDE.md` для инструкций по запуску)

## Быстрый старт

```bash
cd loadtest

# 100 RPS, 30 секунд
go run . -rps 100 -duration 30s

# 200 RPS, 60 секунд, с сохранением CSV
go run . -rps 200 -duration 60s -out results.csv

# Сервер на удалённом хосте
go run . -base http://192.168.1.10:8080 -rps 100 -duration 30s
```

## Флаги

| Флаг | По умолчанию | Описание |
|---|---|---|
| `-base` | `http://localhost:8080` | Базовый URL сервера |
| `-rps` | `100` | Целевое число запросов в секунду |
| `-duration` | `30s` | Длительность теста |
| `-workers` | `50` | Число параллельных горутин |
| `-admin-email` | `admin@corp.local` | E-mail администратора |
| `-admin-pass` | `admin123` | Пароль администратора |
| `-warmup` | `3` | Прогрев в секундах (не входит в статистику) |
| `-out` | _(не задан)_ | Путь для сохранения латентностей в CSV |

## Как работает

### Подготовка (выполняется автоматически перед тестом)

1. Вход под учётной записью администратора
2. Регистрация 5 тестовых пользователей (`loadtest_userN_<ts>@test.local`)
3. Создание 3 тестовых ресурсов типа `meeting_room`

### Сценарии нагрузки

Запросы выбираются случайно с учётом весов, имитируя реальный профиль использования:

| Сценарий | Вес | Доля при 100 RPS |
|---|---|---|
| `GET /availability` | 20 | ~20 RPS |
| `GET /bookings/my` | 20 | ~20 RPS |
| `POST /bookings` | 20 | ~20 RPS |
| `GET /resources` | 15 | ~15 RPS |
| `GET /admin/bookings` | 8 | ~8 RPS |
| `GET /recommendations/schedule` | 7 | ~7 RPS |
| `GET /health` | 5 | ~5 RPS |
| `GET /admin/reports/utilization` | 5 | ~5 RPS |

### Контроль скорости

Используется token bucket: тикер с интервалом `1s / RPS` распределяет задания по пулу воркеров. Это обеспечивает равномерный поток без всплесков.

## Метрики

- **Реальный RPS** — фактическое число запросов в секунду за время теста
- **Ошибки** — HTTP 5xx и сетевые ошибки (4xx не считаются ошибками, т.к. часть броней будет конфликтовать намеренно)
- **p50 / p95 / p99** — процентили латентности: 50-й показывает типичный отклик, 95-й и 99-й — хвост распределения

## CSV-вывод

При указании `-out results.csv` создаётся файл с латентностями для построения графиков:

```
scenario,latency_ms,status,error
all,4,0,
all,11,0,
...
```
